# Resume data model

- Bullet id is a short hash of normalised text when the bullet is first stored. A bullet keeps its stored id on every later run, including a full rebuild, while it continues: it shares a wording with the stored bullet, or is at least 92% similar to it with the same numbers. So a resume that sorts earlier, or the deletion of the file that first stated the bullet, does not change the id or lose its themes; a bullet whose claim really changed gets a new id and its old curation is reported as orphaned. A bullet seen in several resumes gains `sources`; near-identical text (ratio >= 0.92) becomes a `variant`; materially different claims stay separate, including near-duplicates across resumes. If summaries state different years of experience, ask the user to pick one.
- Layouts. Headings are matched by meaning (a synonym table, so `Experience`, `Career Highlights`, `Core Competencies` work; known sections that are not stored, such as awards, end the section before them), dates may be `09/2021`, `Sep 2021` or `2012` (a year-only date is stored as `YYYY`), and a job header may be `Company | Title | dates`, title first, or several titles under one employer. PDF pages with a side bar are read column by column (`resumes/columns.py`); Word text boxes, layout tables (Word, and Markdown grid and pipe tables) and style bullets are read as the page shows them. Two layouts are the base case. A: `WORK EXPERIENCE`, `Company  dates`, title below, `•`, `Present`. B: `Work History`, `Company – Title`, `Role:`/`Client:`, `●`, `§` profile points, `Current`. A third entry shape is also found: `Company`, `Title`, `dates` on three lines (the line above the dates counts as the title only when it holds a job-title word and the line above it could be a company name). Work history is parsed from `pdftotext -layout`; other sections from default reading order (a PDF with columns uses the column-by-column text for both). `process-resumes --survey` names the PDF pages read as columns and reports what looks wrong (unknown heading, heading inside a bullet, bullets inferred from line breaks).
- Curation survives rebuilds and is changed only with `process-resumes curate list|add|rm` (certifications and education to keep: a curated list with any entry replaces the parsed one, an empty one counts as none; skill merge/drop/group, tag-only and extra skills, `wrong-metric` figures, bullet `theme`s, `ignore`d fragments, `summary-angle`s); bullets with a listed wrong figure are flagged `needs_review` and hidden from `for-jd` by default. A changed curation makes the next `process-resumes` rebuild from the files (removals take effect without `--force`). Curation entries name bullets by id and are not linked to them: an id can change when a resume is edited, and such entries are reported as orphaned, never removed.
- Quality words (Security, Performance, ...) are bullet tags, not skills.
